# Spike Data Collection Guide
## S1.1 — CVAT Setup & Dataset Acquisition Protocol

**Version:** 1.0  
**Status:** Active  
**Spike Target:** Validate HSV → YOLO sensing accuracy (MAE ≤ 0.125 HU, Verdict Accuracy > 90%)

## Part 1: CVAT Environment Setup

### 1.1 Installation (Docker — рекомендуется)

```bash
git clone https://github.com/cvat-ai/cvat
cd cvat
docker compose up -d
# UI: http://localhost:8080
# Default login: admin / admin (сменить сразу)
```

### 1.2 Создание проекта

1. **Projects → Create new project**
2. **Name:** `aim-coach-spike-v1`
3. **Labels** (создать ровно два класса):

| Label Name | Color | Attributes |
|---|---|---|
| `head` | #FF0000 (Red) | `occluded`: checkbox |
| `crosshair` | #00FF00 (Green) | — |

4. **Annotation format:** CVAT для видео (XML 1.1) — обеспечивает interpolation между кадрами.

### 1.3 Настройка задачи (Task)

При создании Task для каждого клипа:
- **Frame step:** 1 (каждый кадр)
- **Segment size:** 200 кадров (оптимально для разметчика)
- **Image quality:** 100%

## Part 2: Формирование датасета (30 клипов)

### 2.1 Структура датасета

Датасет делится на три категории с равным весом:

| Категория | Кол-во | Цель | Что проверяем |
|---|---|---|---|
| **Control** (Норма) | 10 | Игроки с хорошим плейсментом (Diamond+) | False Positives — система НЕ должна говорить «проблема» |
| **Target** (Ошибка) | 10 | Явное систематическое занижение прицела | Recall — система ДОЛЖНА поймать проблему |
| **Adversarial** (Шум) | 10 | «Ловушки» для сенсинга | Устойчивость Confidence Layer |

### 2.2 Критерии отбора клипов

**Control-клипы (10 шт.):**
- Источник: Ваши записи ИЛИ YouTube «Valorant Radiant aimplay»
- Критерий: Прицел уверенно на уровне головы в 70%+ дуэлей
- Длина: 8–15 секунд, 3–6 видимых дуэлей в каждом

**Target-клипы (10 шт.):**
- Источник: Ваши записи (легче подобрать) ИЛИ YouTube «Valorant aim mistakes»
- Критерий: Прицел систематически ниже уровня шеи/груди
- Длина: 8–15 секунд, минимум 4 дуэли

**Adversarial-клипы (10 шт.) — распределение:**

| Тип ловушки | Кол-во | Поисковый запрос |
|---|---|---|
| Смоки (частичное перекрытие) | 2 | «Valorant Jett smoke duel» |
| Флеши (белый экран) | 2 | «Valorant flash peek» |
| Несколько врагов в кадре | 2 | «Valorant 2v1 clutch» |
| Разные `enemy_highlight_color` | 2 | Использовать свои записи с изменёнными настройками |
| Экстремальная дистанция | 2 | «Valorant long range duel» |

## Part 3: Протокол Разметки (Ground Truth)

### 3.1 Что размечать

Размечаем **только кадры внутри окон VisualContact**.  
Начало окна = момент появления врага в кадре.  
Конец окна = смерть врага / потеря контакта / выстрел.

> ⚠️ **Важно:** Engagement Logic в этом Spike не тестируется.  
> Окна VisualContact определяются разметчиком вручную, а не алгоритмом.

### 3.2 Пошаговая инструкция для разметчика

**Шаг 1:** Просмотрите клип полностью перед разметкой.

**Шаг 2:** Найдите кадр появления врага. Поставьте bounding box на `head`:
- Охватывает только голову (не тело)
- Включает небольшой отступ: +5px с каждой стороны
- Флаг `occluded = true` если голова перекрыта > 50%

**Шаг 3:** Поставьте точечный bounding box (1×1 px) на `crosshair`:
- Центр прицела игрока (белая точка / крестик)
- Если прицел не виден — пропустить кадр

**Шаг 4:** Используйте **interpolation** CVAT для промежуточных кадров.  
Исправляйте интерполяцию на каждом 3-м кадре для fast-moving targets.

**Шаг 5:** По окончании окна VisualContact — поставьте keyframe с флагом `outside = true`.

### 3.3 Что НЕ размечать

- Кадры вне окон VisualContact
- Кадры с `occluded = true` на голове (голова полностью скрыта)
- Кадры во время флеши (белый экран)
- Кадры, где прицел не виден

### 3.4 Экспорт данных

После разметки: **Export task → CVAT for Video (XML 1.1)** или **COCO 1.0 JSON**.

Нужные поля из экспорта:
```
frame_id → timestamp_ms (frame_id / fps * 1000)
head_bbox → [x, y, w, h] → center = (x + w/2, y + h/2)
crosshair_point → [x, y]
head_height_px → h из head_bbox
```

## Part 4: Inter-Rater Reliability (Контроль качества)

### 4.1 Какие клипы дублировать

Выбрать **6 клипов** (20% от 30) для двойной разметки:
- 2 Control
- 2 Target  
- 2 Adversarial

Разметчик 2 работает с теми же клипами **независимо**, не видя результатов Разметчика 1.

### 4.2 Метрика согласия

После разметки считаем расхождение для каждого кадра:

```python
delta_hu = abs(rater1_offset_hu - rater2_offset_hu)
```

| Результат | Вывод |
|---|---|
| `delta_hu < 0.1` для >85% кадров | ✅ Эталон надёжен |
| `delta_hu < 0.1` для 70–85% кадров | ⚠️ Пересмотреть инструкцию, переразметить спорные кадры |
| `delta_hu < 0.1` для <70% кадров | ❌ Инструкция не работает — остановить Spike, уточнить протокол |

> Это **пол точности** (floor). MAE системы не может быть лучше, чем согласие разметчиков.
