# Дизайн: фронт аккаунтов Discord (Этап 2, Gate 2)

Дата: 2026-07-19. Статус: одобрен; правки по ревью против кода внесены
2026-07-19.

## Цель

Закрыть пользовательский путь Этапа 2: вход через Discord, отображение
аккаунта, история своих клипов, кнопка «Поделиться» отчётом. Бэкенд
(AUTH_MODE=discord, JWT-кука, share-токены) уже готов — фронта нет.

## Объём

Полный Этап 2-фронт: логин + шапка с аккаунтом + история + share-кнопка.
Вне объёма: платный тир, страница профилей игрока, отдельный роутер.

## 1. Бэкенд-дополнения (минимальные)

- `GET /api/v1/auth/me` → добавить поле `mode: "off" | "discord"` к
  текущему ответу `{user}`. Один запрос при старте даёт фронту и режим,
  и пользователя.
- `GET /api/v1/auth/me` → добавить `avatar_url` (готовый URL, собирает
  СЕРВЕР): фронт собрать его не может — `/me` отдаёт внутренний UUID и хэш
  аватара, а для CDN-URL (`cdn.discordapp.com/avatars/{discord_id}/{hash}.png`)
  нужен discord_id, который наружу не отдаётся (и не должен). При
  `avatar=null` сервер отдаёт дефолтную эмбед-аватарку Discord по их формуле.
- `POST /auth/logout` → отдавать `{ok: true}` вместо RedirectResponse 303:
  клиент — fetch, редирект на HTML фронта ему не нужен (одна строка).
- Новый `GET /api/v1/analysis` — список сессий текущего владельца:
  `[{session_id, status, player_id, clip_id, created_at}]`,
  сортировка по `created_at` убыв., параметр `limit` (default 20, max 100).
  - `AUTH_MODE=off`: возвращает анонимные сессии (owner IS NULL) —
    dev-режим, один пользователь.
  - `mode=discord`, гость: пустой список `[]` (не 401 — проще для фронта).
- `is_owner` и `share_token` в `GET /api/v1/analysis/{id}` УЖЕ отдаются
  (main.py: владельцу — оба, гостю share_token не отдаётся) — бэкенд-правка
  не нужна.

## 2. Фронт — состояние auth

- `src/api.js`: `getMe()`, `getLoginUrl()`, `logout()`, `listSessions()`,
  `createShareLink(sessionId)`; все fetch с `credentials: "include"`
  (JWT в httpOnly-куке).
- Хук `src/hooks/useAuth.js`: при монтировании один запрос `/auth/me` →
  `{ mode, user, loading }`. Без глобального стора — состояние живёт в
  App и передаётся пропсами.

## 3. UI-компоненты (стиль HUD из DESIGN.md)

- `AuthBar` (шапка):
  - `mode=off` → не рендерится;
  - гость → кнопка «Войти через Discord»: GET `/auth/login` → редирект
    на полученный `url`;
  - залогинен → аватар (`avatar_url` из `/me` как есть) + ник + кнопка
    «Выйти» (POST `/auth/logout`, затем перезапрос `/me`).
- `SessionHistory` (под формой загрузки): последние разборы — статус-бейдж
  (COMPLETED/FAILED/в работе), дата, player_id; клик → `?session=<id>`
  (существующий механизм URL-сессии). Сессии «в работе» включаются; клик по
  такой строке попадает на существующий экран прогресса (App это уже умеет —
  зафиксировать тестом). Не рендерится при пустом списке.
- Кнопка «Поделиться» в `ReportView` — только при `is_owner=true`:
  если `share_token` уже пришёл в GET — ссылка строится сразу, без запроса;
  иначе POST `/analysis/{id}/share`. Ссылка вида
  `<origin>/?session=<id>&share=<token>` копируется в буфер,
  тост «Ссылка скопирована»; при сбое копирования (clipboard API требует
  HTTPS — на HTTP-проде молча сломается) фолбэк: показать ссылку текстом
  для ручного копирования. Фронт при поллинге передаёт `share` из URL
  в `GET /analysis/{id}?share=...` (гостевой доступ).

## 4. Ошибки

- 404 при поллинге чужой/несуществующей сессии (бэкенд сознательно не
  подтверждает существование чужих; 401 в этом пути не бывает) и 400 для
  битого ID → экран «Отчёт недоступен — войдите или запросите ссылку у
  владельца».
- Ошибка Discord на callback (502) обрабатывается бэком; фронт просто
  остаётся гостем.
- Зафиксировано вне объёма: OAuth state не привязан к браузеру двойной
  проверкой через куку — от подделки значения защищает, от login-CSRF нет;
  для этого продукта риск принят, решение не требуется.

## 5. Тесты

- pytest: `mode` в `/me` (off и discord); `avatar_url` — с хэшем и при
  `avatar=null` (дефолтная эмбед-аватарка); logout отдаёт `{ok: true}`;
  list-эндпоинт — владелец видит своё, чужое не видит, off-режим отдаёт
  анонимные, гость — `[]`, limit работает.
- Фронт (react-testing-library): ветки рендера `AuthBar`
  (off/гость/залогинен), `SessionHistory` (пусто/список; клик по строке
  «в работе» → экран прогресса), share-кнопка видна только владельцу и
  строит ссылку без POST при уже пришедшем `share_token`; фолбэк
  показа ссылки текстом при сбое clipboard.
- Живой OAuth-прогон: требует Discord-приложение
  (discord.com/developers → client_id/secret в `.env`) — ручное действие
  пользователя по инструкции.
