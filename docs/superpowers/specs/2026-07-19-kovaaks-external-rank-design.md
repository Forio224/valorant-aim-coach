# Дизайн: внешний ранк KovaaK's (Voltaic S5) в петле прогресса

Дата: 2026-07-19. Статус: правки по ревью внесены, на повторное ревью.

## Цель

Автоматически подтягивать ранк и посценарные скоры игрока по бенчмаркам
Voltaic S5 из веб-API KovaaK's — пользователь один раз указывает SteamID64
вместо ручного ввода ранка. Данные питают: (1) механический выбор тира
дриллов, (2) внешний сигнал двухсигнальной прогрессии Фазы 2C, (3) контекст
коуча.

Источник: `kovaaks.com/webapp-backend/benchmarks/player-progress-rank-benchmark
?benchmarkId=&steamId=` — отвечает без авторизации, отдаёт `overall_rank`,
`benchmark_progress` и по каждому сценарию `score` / `scenario_rank` /
`rank_maxes`. Проверено вживую 2026-07-19. **API неофициальный** — интеграция
только мягкая: любой сбой деградирует в «данных нет», никогда в FAILED.

## Объём

Клиент API + хранение снапшота + механический гейт тира в меню дриллов +
заземление в валидаторе + отображение на фронте. Вне объёма: Aimlabs
(Valorant-бенчмарк — отдельный API, отдельная спека), скрейпинг voltaic.gg,
Steam OAuth, автопрогрессия тира внутри плана (Фаза 2C).

## 1. Клиент (`backend/services/kovaaks_client.py`)

- `fetch_benchmark_progress(steam_id) -> Optional[ExternalBenchmark]` —
  запрашивает три benchmarkId S5 (Novice/Intermediate/Advanced) из env
  `KOVAAKS_S5_BENCHMARK_IDS`. Три запроса идут параллельно с ОБЩИМ бюджетом
  6 с на все.
- **Частичный сбой — частичный снапшот**: каждый тир независим; ответивший
  тир пишется, упавший — попадает в `tiers_failed` (для отладки). Потребители
  обязаны терпеть отсутствие любого тира: нет тира = нет скоров (в т.ч. для
  гейта: отсутствующий тир ничего не открывает).
- Полный сбой (все три) или нет steam_id → блока нет +
  `external_unavailable_reason` из перечня: `"no_steam_id" | "api_error" |
  "no_scores"`. Приватный профиль от пустого неотличим на неофициальном API —
  честно НЕ выделяем его в отдельную причину, это `no_scores`.
  Контракт на отсутствие данных обязателен: ни один потребитель не
  предполагает наличие блока.
- **Кэш** снапшота по steam_id на 1 час (in-memory, прецедент rate_limit) —
  вежливость к чужому API: повторная загрузка клипа не бьёт в сеть.
- SteamID64 валидируется механически (17 цифр) на приёме формы → 422 с
  человеческим текстом, мусор до сети не доходит.

## 2. Данные и хранение

- Снапшот пишется в `AnalysisSession` (JSON-колонка `external_benchmark`)
  на шаге MEASURING, до коуча:

```
{"source": "kovaaks_webapp_unofficial", "fetched_at": "<UTC ISO>",
 "season": "S5", "tiers_failed": [],
 "tiers": {"novice": {"overall_rank": ..., "benchmark_progress": ...,
                      "scenarios": {"<имя из API>": {"score": ...,
                                    "scenario_rank": ..., "rank_maxes": [...]}}},
           "intermediate": {...}, "advanced": {...}}}
```

- Имя честное: `source` называет неофициальный API поимённо; блок называется
  `external_benchmark`, не «rank» — это чужие измерения, не наши.
- **Приватность: steam_id в снапшоте НЕТ.** Отчёт при `AUTH_MODE=discord`
  доступен гостю по share-токену, а SteamID64 — публичный идентификатор
  всего Steam-профиля человека; в шаринг он утекать не должен. Steam ID живёт
  только там, где хранится: на аккаунте (users, миграция) при `discord`,
  в поле формы (как sens/eDPI) при `off`. Тест фиксирует: в evidence-JSON
  и share-выдаче подстроки steam_id нет.
- В evidence-JSON блок попадает как `external_benchmark` (или
  `external_unavailable_reason`). SCHEMA_VERSION бампается ТЕМ ЖЕ коммитом,
  что вводит поле.

## 3. Связка с каталогом дриллов

- `CatalogDrill` получает поле `kovaaks_scenario: Optional[str]` — точное имя
  сценария в API (ww5t/1wNts/Pasu по тирам). Ключ соединения «наш дрилл ↔
  внешний скор»; drill_id не трогаем (Фаза 2 ключуется на них).
- Механические правила меню (валидатор гейтит фактами, не промптом):
  1. `external_benchmark` есть и в нём хоть один `score > 0` → KovaaK's-дриллы
     входят в меню независимо от `training_platform` (факт владения
     тренажёром сильнее анкеты; None-схлопывание в ingame для остальных
     не меняется).
  2. Тир T метрики доступен **только для kovaaks-дриллов**, если её сценарий
     тира T имеет `score > 0` (игрок его уже играет) ИЛИ сценарий тира T−1
     достиг верхнего порога тира (определение ниже). Иначе — tier 1, как
     сейчас. **ingame/range-дриллы внешний гейт не трогает** (остаются
     tier 1): грайнд сценария в тренажёре не доказывает перенос в игру —
     перенос принципиально меряет движок на клипах.
- **Единый источник порогов**: верхний порог тира = последний элемент
  `rank_maxes` сценария из снапшота (массив упорядочен по возрастанию);
  каталожные `rank_thresholds` — фолбэк, только если тира нет в снапшоте
  (формально: `max(rank_thresholds.values())`). Коучу в промпт идут РОВНО
  те числа, которые ел гейт, — игрок никогда не видит от коуча один порог,
  а от гейта другое поведение. Фикстурный тест ловит дрейф каталога от API.
- **Граница с Фазой 2C**: правило 2 — это ДОПУСК в меню (статика: что вообще
  можно назначить), не рекомендация перехода. Прогрессия «пора на тир выше» —
  целиком 2C, и внешний сигнал там не считается дважды: 2C сравнивает
  динамику скоров между клипами, гейт лишь открывает дверь.
- Анти-сирота: у каждой метрики при любом исходе гейта остаётся ≥1 вариант
  в меню (placement внешним гейтом не трогается — у Voltaic нет пре-айма).

## 4. Коуч и заземление (тем же коммитом)

- Промпт получает блок внешних скоров как факты движка (числа копируются,
  не пересчитываются). Коуч может сослаться «твой Pasu — 812, порог
  Intermediate — 770», но не обязан.
- `coach/validate.py`: множество допустимых чисел расширяется числами из
  `external_benchmark` (score/rank_maxes/пороги) — упоминание скора, которого
  нет в JSON, ловится так же, как выдуманный HU.
- Каталожное правило тира в промпте дублируется, но истиной остаётся
  механический гейт `menu_drill_ids` — промпт может ошибиться, валидатор нет.

## 5. Фронт

- `UploadForm`: опциональное поле «SteamID64 (для ранга KovaaK's)» с
  подсказкой, где его взять; при `AUTH_MODE=discord` и сохранённом ID поле
  предзаполнено.
- `ReportView`: строка внешнего ранга (тир + ранг + скор назначенного
  сценария) — только при наличии блока; при `external_unavailable_reason`
  ничего не показываем (без пугающих ошибок, причина видна в JSON).

## 6. Тесты

- Клиент: мок HTTP — успех, таймаут, 404, невалидный JSON, нулевые скоры →
  корректный reason; частичный сбой → частичный снапшот с `tiers_failed`;
  кэш отдаёт снапшот без второго сетевого вызова; сеть в тестах не трогается.
- Приватность: steam_id отсутствует в evidence-JSON и share-выдаче
  (проверка подстроки на реальном форматe сессии).
- Меню: гейт тира по обоим правилам и только для kovaaks-дриллов
  (ingame/range не разблокируются), пороги из снапшота побеждают каталожные,
  отсутствующий тир не открывает следующий, анти-сирота на каждую метрику,
  включение kovaaks по факту скоров, отсутствие блока = поведение как сегодня
  (регресс-инвариант).
- Валидатор: внешнее число проходит, выдуманное — ловится; ретрай/деградация
  как у прочих нарушений.
- Пайплайн: сбой клиента не роняет сессию (COMPLETED без блока).
- Живой прогон на реальном SteamID автора — ручной, по инструкции.

## Риски

- API неофициальный: может измениться/закрыться. Митигация — мягкая
  деградация всюду + один модуль-клиент (менять в одном месте).
- Смена сезона Voltaic — честно КОДОВАЯ правка, не только env: benchmarkId
  (env), `kovaaks_scenario` и `rank_thresholds` в каталоге (код) обновляются
  одним коммитом; тест фиксирует соответствие каталога и снапшота-фикстуры.
  Внутрисезонные правки порогов Voltaic'ом переживаются без кода: гейт и
  коуч читают живые `rank_maxes` из снапшота, каталог — лишь фолбэк.
- Чужой SteamID подставить можно — это самоотчёт с той же честностью, что
  sens/eDPI; на выводы движка (клипы) не влияет, только на меню дриллов.
