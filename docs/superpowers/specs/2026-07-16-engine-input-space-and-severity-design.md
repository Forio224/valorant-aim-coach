# Input-space, качество сигнала фликов, severity и in-game каталог

**Дата:** 2026-07-16
**Статус:** дизайн, **заблокирован до влития Фазы 3 в код** — спека ссылается на
`engine/geometry.py`, схему отчёта 1.2 и `METRICS_VERSION`, которых на main ещё
нет. План по этой спеке не пишется, пока Фаза 3 не в коде.
**Фаза:** 4 (движок + коуч; база — main после Фазы 3)

## Цель

Четыре независимых улучшения, каждое закрывает проверенное слабое место:

1. **Качество сигнала фликов** — `_settle_index` считает «k подряд» по индексам
   сэмплов, а не по кадрам; на дырявом YOLO-треке три «подряд» растягиваются на
   пятнадцать кадров, jitter завышается склейкой дельт через дырку, path
   занижается недосэмплированием. Плюс гейт плотности детекций как страховка.
2. **Input-space** — sens/eDPI едут в отчёт мёртвым грузом, а `_symmetry_note`
   говорит «похоже на сенсу», не глядя на сенсу. Движок начинает считать
   cm/360 и см-эквивалент перелёта; нота становится условной.
3. **Severity как факт** — приоритизация находок сейчас полностью языковая
   (промпт). Движок публикует отклонение каждой находки от её собственного
   порога; валидатор жёстко гейтит только заземлённое — порядок классов
   уверенности.
4. **In-game ветка каталога** — consistency/bias/correction лечатся только
   KovaaK's; добавляются Valorant-альтернативы всем трём + `training_platform`
   как пятый user-supplied факт, чтобы выбор платформы не был гаданием VLM.

## Управляющий принцип (наследуется)

Числа считает ТОЛЬКО движок; если сигнала в данных нет — движок молчит, а не
догадывается. Следствия, определившие границы этой спеки:

- **Кросс-метрического ранга severity нет.** Обменный курс между «долей
  появлений ниже линии» и «HU разброса» взять неоткуда; ранжирование поверх
  некалиброванных порогов наследовало бы произвол дважды. Движок даёт факт
  внутри метрики, порядок между метриками — суждение VLM под заземлённым
  гейтом.
- **Сантиметры — эквивалент, не измерение.** Перелёт — output-space прокси
  (стрейф врага неотделим от руки на одноголовом флике); поле называется
  `*_cm_equiv_*` и читается как «столько руки объяснило бы перелёт целиком».
- **Предпочтение платформы не выводится.** Это user-supplied факт того же
  класса, что sens/agent/map_name: игрок его знает, видео его не видит.

## Скоуп

**В спеке:** четыре компонента выше + схема 1.3 + `METRICS_VERSION` → 3.

**Явно вне:**

- **`by_distance`-стратификация метрик** — отклонена ревью: три бакета × четыре
  фаз-метрики = множественные сравнения («худшее из 12» найдётся у любого), а
  бакет = settled − sparse при пороге 3 почти всегда insufficient. Паркуется до
  `dataset1/` и фазы статистической честности.
- **Детекция ADS/зума** — Operator в прицеле ≈ 2.5×, cm-поля при зуме неверны
  в разы. Наблюдаемый признак есть (высота всех голов рвётся скачком разом),
  но это отдельная работа с калибровкой. Сейчас — поимённый кавеат.
- **Нормы по рангам, пользовательские цели** — нет данных / продуктовый сахар.
- Замена KovaaK's-дриллов (история 2B ключуется на drill_id, Voltaic
  rank_thresholds нужны 2C) — только параллельная ветка.

## Компонент 1: качество сигнала фликов

### Починка (сначала), гейт (потом, как страховка)

`engine/metrics/flick_phase.py`:

- **`_settle_index` переезжает в кадровое пространство.** Прогон продолжается
  только по кадрово-смежным сэмплам (`frame_idx` ровно +1); разрыв кадра
  сбрасывает прогон. Квалификация — прогон покрывает ≥ `SETTLE_STABLE_FRAMES`
  подряд идущих кадров. Ложное «оселся» по обе стороны дырки исчезает.
- **`settle_jitter_hu` — только кадрово-смежные дельты.** Дельта через дырку —
  склейка двух движений, завышает pstdev на ровном месте. Если смежных пар в
  settle-сегменте < 2 → `None`, а не мусорное число. Сегмент jitter'а — подход
  ДО точки успокоения (`radials[b:s+1]`), а требование смежности settle-прогона
  относится к кадрам ПОСЛЕ неё — поэтому settled-флик с дырявым подходом
  легально даёт jitter `None`.
- **`correction_path_hu` остаётся суммой |Δ|** — при дырках это нижняя оценка
  пути; гейт плотности ограничивает недосэмплирование. Кавеат обновляется:
  «путь — нижняя оценка при пропусках детекции».

### Контракт медиан при None (регрессия, найденная на ревью)

`_med` сейчас не фильтрует `None` — `statistics.median` упал бы TypeError на
первом же флике с jitter=None. Решение:

- `usable` остаётся = settled (вход всех четырёх фаз-метрик);
- каждая медиана считается по non-None значениям своей метрики;
- values получают `flicks_jitter_n` — сколько фликов реально дали jitter
  (path/overshoot/settle_time у settled-флика не бывают None, им свой n не
  нужен);
- `phase_confidence` остаётся по числу settled, но
  **`settle_jitter_hu_median` = `None` при `flicks_jitter_n <
  MIN_FLICKS_FOR_PHASE`** — иначе confidence-лейбл находки (по settled) дал бы
  коучу право утвердительного языка про рывковость, померенную на одном флике.
  Нет сигнала — движок молчит; `flicks_jitter_n` при этом публикуется, чтобы
  было видно, почему медиана пуста.

### Гейт плотности

- Хелпер `detection_density(ep) = len(ep.samples) / (end_frame − start_frame + 1)`
  в `engine/episodes.py`.
- Ручка `MIN_FLICK_DETECTION_DENSITY = 0.7` (некалибр.).
- Разреженный флик получает `sparse=True`: **считается** (`flicks_sparse` в
  values), но исключается из вердиктов, медиан и знаменателя confidence.
- Гейт применяют оба потребителя фликов — `flick_phase` И `correction`, — чтобы
  эпизод не был «слишком дырявый для фаз, но годный для перелёта».

### Версия методики

Определения `flicks_analysed`, медиан и счётчиков перелёта меняются →
`METRICS_VERSION` 2 → **3** в том же коммите, что settle-фикс + гейт. Фильтр
агрегации Фазы 3 отработает сам; anchor-серии 2B смену методики за прогресс не
посчитают.

### Честные отказы — раздельно по полям

`cm_per_360` — чистая мышиная арифметика, ни ширины кадра, ни FOV в формуле
нет; аспект её не трогает. FOV нужен только на пути HU → градусы. Поэтому:

- **`cm_per_360`**: `None` только при отсутствии `edpi`. На stretched res
  сенса игрока известна точно — зануление было бы враньём.
- **`flick_overshoot_cm_equiv_median`**: `None` при отсутствии `edpi` ИЛИ
  аспекте не 16:9 (FOV-модель не валидна для stretched res); причина — в
  `clip.cm_unavailable_reason` (nullable-строка, см. схему 1.3).
- Условная `_symmetry_note` зависит только от `cm_per_360` и продолжает
  работать на stretched res.

### Куда едет

- `clip`-блок отчёта: `cm_per_360` (nullable).
- values находки `correction`: `flick_overshoot_cm_equiv_median` — медиана по
  тем же usable-фликам, что HU-медиана; конверсия по высоте головы на кадре
  улики перелёта.
- Кавеат при cm-полях, поимённо: «см — эквивалент хода мыши, не измерение
  (стрейф врага неотделим); валидно для стрельбы с бедра — Operator в прицеле
  ≈ 2.5×, сигнала о зуме в данных нет».

### Условная `_symmetry_note`

Ручки: `SENS_HIGH_CM360 = 30.0`, `SENS_LOW_CM360 = 60.0` (некалибр., быстрее
30 см/360 — «высокая сенса»). При симметричном перелёте:

- сенса известна и высокая → «…и сенса высокая (N см/360) — сенса-подобная
  гипотеза усиливается»;
- известна и умеренная/низкая → «…но сенса умеренная (N см/360) — смотри в
  сторону доводки/мышечной памяти»;
- неизвестна → текущий текст без изменений.

Язык всюду гипотезный — это нота, не вердикт.

### Заземление сантиметров (тот же этап, что вводит cm-поля)

`coach/validate.py`:

- `_CM_NUMBER_RE` — параллельный `_HU_NUMBER_RE` регексп на `см|cm`, та же
  проверка с допуском на округление;
- пул чисел расширяется **явно** на `clip.cm_per_360` — `_known_numbers`
  сегодня собирает findings/episodes/profile и НЕ видит clip-блок;
  `flick_overshoot_cm_equiv_median` попадает в пул автоматически через values.

Между введением cm-полей и их заземлением не существует ни одного коммита —
иначе есть версия, где выдумывать сантиметры разрешено.

## Компонент 3: severity как факт + заземлённый гейт

### severity_ratio (в каждой находке, per-metric)

Отклонение от **собственного** порога находки — измеримый безразмерный факт
внутри метрики:

| Метрика | Числитель | Порог |
|---|---|---|
| placement | `below / total_gated` | `PLACEMENT_TARGET_FRACTION` (0.2) |
| consistency | величина, определившая диагноз (std при «повторяемости», mae при «калибровке» — зеркалит порядок `_classify`) | свой порог этой величины |
| bias | `abs(y_bias_hu)` | `BIAS_HIGH_HU = 0.5` (некалибр.) |
| correction | доля худшей оси (max перелёт/недолёт) | `CORRECTION_HIGH_SHARE = 0.5` (некалибр.) |

Для consistency ratio намеренно берётся от диагнозной величины, а не от max:
иначе при std 1.1 / mae 3.0 диагноз скажет «повторяемость», а severity придёт
от калибровки — два факта в разные стороны. Оставшиеся диагнозы consistency:
`stable_accurate` → `max(std_ratio, mae_ratio)` (оба < 1, показывает запас до
ближайшего порога); `insufficient` — по общему контракту ниже.

### Контракт на отсутствие данных (обязателен: без него пустой клип роняет пайплайн)

`severity_ratio: Optional[float]`, сериализуется через `_r()` (NaN → `None`),
**никогда сырым числом**. `None`, когда числителя арифметически нет:

- consistency при нуле дуэльных кадров — `compute_consistency` возвращает NaN
  в mae/std, а `report_to_json` работает с `allow_nan=False`;
- bias при `y_bias_hu is None` — `abs(None)` это TypeError;
- correction при `flicks_analysed == 0` — деление на ноль, и после гейта
  плотности ноль достижим на реальном клипе.

Если величина существует и конечна (в т.ч. у insufficient-находки с малым, но
ненулевым n) — ratio считается и публикуется; интерпретацию ограничивает
confidence-лейбл находки.

**Кросс-метрического ранга нет** (см. управляющий принцип).

### Гейт валидатора (жёсткий — только на факте движка)

Правило монотонности по трём уровням: при сортировке дриллов по `priority`
класс уверенности целевой находки **не возрастает** —
diagnosis ≥ hypothesis ≥ insufficient. Механически: `drill_id → catalog.metric
→ finding.confidence`, одно сравнение. Нарушение — обычный путь: ошибка →
ретрай → coach_failed.

Внутри одного класса порядок выбирает VLM и мотивирует в rationale; промпт
получает правило и severity_ratio как контекст.

## Компонент 4: in-game каталог + training_platform

### Каталог (`coach/drill_catalog.py`)

Параллельные ветки для **всех трёх kovaaks-метрик** — по три тира, новые
стабильные drill_id, `platform="range"|"ingame"`, `rank_thresholds=None`
(у Valorant нет счёта Voltaic):

- `consistency_ingame_t1..t3` — Range/DM: одиночные в голову на стабильном
  темпе (повторяемость без тренажёра);
- `bias_ingame_t1..t3` — Range: одиночная постановка с контролем, куда легла
  пуля относительно головы (систематическое смещение видно без тренажёра);
- `correction_ingame_t1..t3` — Range/DM: осознанные флики на новые цели с
  доводкой без проскока.

**Почему bias обязателен, а не опционален:** tier-1 у bias сегодня — только
kovaaks (`bias_t1_vt_1w4ts_novice`). Без in-game ветки правило «kovaaks
исключены при "ingame"» оставило бы bias-находку вообще без легального дрилла:
VLM либо бросает находку, либо берёт id вне меню → ретрай → coach_failed.
Игрок, честно указавший «тренируюсь в игре», систематически терял бы план по
самой калибровочной находке. Симметричная ветка закрывает дырку без
спец-случаев в правиле меню.

Дозы/инструкции — доменно-правимые строки, как у placement. Старые id не
тронуты: история 2B и rank_thresholds для 2C целы.

### training_platform (пятый user-supplied факт)

`ClipContext.training_platform: Optional[str]` — `"kovaaks" | "ingame"`,
докстрока наследует формулировку: user-supplied input-space fact, carried
verbatim, never inferred. Проброс: CLI-флаг `--training-platform`, поле формы
API (опциональный селект в UploadForm), `clip`-блок отчёта.

### Меню — механический фильтр, не просьба в промпте

`menu_drill_ids` начинает считаться от контекста клипа (валидатор читает его из
`clip`-блока evidence-JSON):

- `"ingame"` → KovaaK's-дриллы исключены из меню (остаётся по одному tier-1
  варианту на каждую из четырёх метрик) — выбор гейтится **валидатором**, как
  сейчас гейтится tier;
- `"kovaaks"` → меню полное (у KovaaK's-игрока есть и Valorant);
- `None` → меню полное; промпт велит дефолтить в ingame-ветку с фиксированной
  формулировкой «платформа не указана — дефолт: тренировка в игре», не
  сочиняя предпочтение игрока.

## Схема отчёта: 1.2 → 1.3 (аддитивно)

`SCHEMA_VERSION` поднимается **в одном коммите с первым новым полем** (этап 2);
последующие этапы добавляют свои поля уже под 1.3, ветка вливается целиком.

Новые поля: `clip.cm_per_360`, `clip.cm_unavailable_reason` (nullable-строка:
почему отсутствует cm-эквивалент — «нет eDPI» / «аспект не 16:9»),
`clip.training_platform`; у correction — `flick_overshoot_cm_equiv_median`,
`flicks_sparse`, `flicks_jitter_n`, обновлённые кавеаты; у всех находок —
`severity_ratio` (Optional, через `_r()`). Фронт не трогаем; граница —
`npm run build`.

## Ручки и их некалиброванность

Все значения — обоснованные дефолты, проверяемые синтетикой; калибровка — когда
появится `dataset1/` (как conf=0.4 на холдауте). Каждая помечается в коде.

| Ручка | Дефолт | Обоснование |
|---|---|---|
| `MIN_FLICK_DETECTION_DENSITY` | 0.7 | грубее — вердикты по дыркам; жёстче — выкинем половину yolo-фликов |
| `SENS_HIGH_CM360` | 30.0 | быстрее ~30 см/360 сообщество зовёт высокой сенсой |
| `SENS_LOW_CM360` | 60.0 | медленнее — заведомо «контрольная» сенса |
| `BIAS_HIGH_HU` | 0.5 | полголовы систематического смещения |
| `CORRECTION_HIGH_SHARE` | 0.5 | худшая ось портит больше половины фликов |

## Проверка

Синтетика, без видео и БД, по образцу существующих тестов движка:

- **Дырявый settle:** сэмплы с разрывом кадра внутри допуска не дают ложного
  «оселся»; jitter при < 2 смежных пар = `None`, отчёт **не падает** (регрессия
  `_med` на None — отдельный тест); `settle_jitter_hu_median` = None при
  `flicks_jitter_n < MIN_FLICKS_FOR_PHASE`, даже когда settled достаточно для
  diagnosis.
- **Плотность:** флик с density < 0.7 помечен sparse, посчитан в
  `flicks_sparse`, исключён из медиан и confidence — в обеих метриках
  (flick_phase и correction).
- **cm/360:** eDPI 280 → 46.65; нет edpi → оба cm-поля None. Аспект 4:3 →
  `cm_per_360` ПРИСУТСТВУЕТ (мышиная арифметика от FOV не зависит),
  `flick_overshoot_cm_equiv_median` = None, причина в
  `cm_unavailable_reason`; symmetry-нота работает.
- **Заземление:** выдуманные сантиметры в тексте коуча → ошибка валидации;
  честное упоминание `cm_per_360` из clip-блока → проходит (пул расширен).
- **Симметрия-нота:** три ветки текста по known/high, known/low, unknown.
- **severity_ratio:** consistency берёт диагнозную величину (std 1.1 / mae 3.0
  → ratio от std); stable_accurate → max двух ratio, оба < 1. **Пустой клип /
  ноль дуэльных кадров / flicks_analysed=0 → ratio = None, отчёт
  СЕРИАЛИЗУЕТСЯ** (`allow_nan=False` — отдельный тест на каждую метрику).
- **Гейт монотонности:** дрилл по hypothesis раньше дрилла по diagnosis →
  ошибка; insufficient в середине → ошибка; равные классы в любом порядке →
  проходит.
- **Меню:** `training_platform="ingame"` → kovaaks-id в ответе VLM = ошибка
  валидации, при этом у КАЖДОЙ из четырёх метрик в меню остаётся tier-1
  вариант (анти-сирота: bias не выпадает); `None` → полное меню из ровно 7 id
  (placement 1 + consistency 2 + bias 2 + correction 2).
- **Регрессия:** существующие тесты движка/коуча зелёные; `npm run build` не
  падает (схема аддитивна).

## Порядок работ

1. Качество сигнала: settle-фикс (кадровое пространство) + jitter по смежным
   дельтам + контракт медиан при None + гейт плотности + `METRICS_VERSION` → 3.
2. `engine/input_space.py` + cm-поля в отчёте + `SCHEMA_VERSION` → 1.3 +
   `_CM_NUMBER_RE` и расширение пула валидатора (одним коммитом с полями).
3. Условная `_symmetry_note`.
4. `severity_ratio` + гейт монотонности в валидаторе + правило в промпте.
5. Каталог: in-game ветки + `training_platform` (ClipContext → CLI → API →
   форма) + контекстное меню в валидаторе.
6. Зелёный прогон + `npm run build`.

## Открытые вопросы

- Детекция ADS по скачку высоты голов (снимет кавеат с cm-полей) — отдельная
  фаза; заодно даст сигнал для weapon-контекста.
- `by_distance` — вернуться после фазы статистической честности, с данными о
  реальных размерах бакетов.
