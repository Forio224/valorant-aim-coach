# План выхода в сеть — Valorant AI Aim Coach

Дата: 2026-07-19. Статус кода на момент плана: Phase A + Phase B (B0–B5)
завершены, каталог дриллов (Фазы 1–4) завершён, редизайн «Спектаторский HUD»
перенесён в frontend, 353 теста зелёные. Продукт работает локально:
клип → браузер.

**Честная рамка.** «Без единой ошибки» не бывает ни у одного продукта —
бывает система, в которой ошибка не доходит до пользователя или чинится
за минуты. Поэтому план построен на воротах качества (gate): каждый этап
имеет чеклист выхода, и следующий не начинается, пока ворота не закрыты.
Ошибки ловятся на staging, в бете и мониторингом — не в проде у игрока.

## Этап 0 — Решения до кода (≈ 3 дня)

Решения, которые дешевле принять сейчас, чем переделывать потом.

- [ ] **Юнит-экономика разбора.** Посчитать на 10 реальных клипах:
      GPU-секунды YOLO на минуту видео + токены коуча (usage-лог уже
      пишется) = себестоимость одного разбора в $. Из неё — лимиты
      бесплатного тира (например, 3 клипа/день) и потолок длины клипа
      (рекомендация: ≤ 2 минуты, лимит уже есть по мегабайтам).
- [ ] **Модель доступа на запуск:** закрытая бета по инвайтам → открытая
      бета с лимитами → платный тир. Платежи НЕ нужны для запуска беты —
      не тащить их в первый релиз.
- [ ] **Имя и домен.** Проверить, что название не использует «Valorant»
      в домене/логотипе (риск с товарным знаком Riot). Формат
      «Aim Passport — aim coach for Valorant» безопаснее.
- [ ] **Юрисдикция и платёжный провайдер** (влияет на ToS): Stripe/Paddle
      или ЮKassa — решить по стране оформления, но только к платному этапу.

**Gate 0:** известна цена разбора в $, выбраны лимиты free-тира, имя не
нарушает чужих знаков.

## Этап 1 — Прод-готовность бэкенда (≈ 1–2 недели)

Сейчас: SQLite + BackgroundTasks + локальные папки. Для одного сервера и
беты этого почти достаточно, но три вещи обязательны.

1. [ ] **Очередь задач вместо BackgroundTasks.** Пайплайн живёт минуты;
       рестарт uvicorn убивает разбор молча. Перевести на arq или RQ
       (Redis): ретраи стадий, воркер отдельным процессом, сессия
       переживает деплой. Идемпотентность по clip_id уже есть — использовать
       её для безопасного повтора.
2. [ ] **PostgreSQL вместо SQLite** (SQLModel остаётся, добавить Alembic
       для миграций). SQLite не переживёт конкурентную запись
       воркер+API на проде.
3. [ ] **Файлы → S3-совместимое хранилище** (Cloudflare R2 — без платы за
       трафик, или Backblaze B2): клипы и улики. Загрузка клипа —
       presigned URL напрямую в хранилище, чтобы 300 МБ не шли через API.
       Ретеншн: исходный клип удаляется через 7 дней (это персональные
       данные и деньги за хранение), улики-JPEG живут с отчётом.
4. [ ] **GPU для YOLO.** Два варианта, выбрать по цене из Этапа 0:
       - serverless GPU (Modal / RunPod serverless): платим за секунды
         инференса, холодный старт ~десятки секунд — для «разбор за
         минуты» приемлемо;
       - один GPU-VPS с постоянным воркером — дешевле при стабильном
         потоке, дороже при нулевом.
       conf=0.4 зафиксирован калибровкой — в конфиге пометить «не трогать».
5. [ ] **Коуч-провайдер.** COACH_PROVIDER уже мульти-провайдерный —
       на прод вынести ключи в секрет-хранилище платформы, включить
       фолбэк: если основной провайдер 5xx/квота — второй, потом
       деградация coach_failed (уже реализована).
6. [ ] **Наблюдаемость:** Sentry на фронт и бэк; структурные логи стадий
       пайплайна с session_id; метрики: длительность DETECTING/MEASURING/
       COACHING, доля FAILED, доля coach_failed. Алерт, если FAILED > 5%
       за час или очередь растёт.
7. [ ] **Мелочи прода:** health-эндпоинт для оркестратора, graceful
       shutdown воркера (дорешать текущую задачу), лимит одновременных
       разборов на воркер.

**Gate 1:** разбор переживает рестарт сервера; два параллельных разбора
не мешают друг другу; файлы в объектном хранилище; ошибки видны в Sentry.

## Этап 2 — Аккаунты, доступ, безопасность (≈ 1 неделя)

Сейчас player_id — свободная строка, а отчёт доступен любому, кто знает
UUID. Для публичного продукта это две дыры.

1. [ ] **Аутентификация.** Discord OAuth — родной для аудитории Valorant
       (плюс email magic-link как запасной). Никаких паролей самим не
       хранить.
2. [ ] **player_id → профили внутри аккаунта.** Принцип «людей не
       смешивать» остаётся: у аккаунта несколько именованных профилей
       (я / смурф / друг), клип привязывается к профилю. Миграция:
       существующие локальные профили — только у автора, в прод едут
       с нуля.
3. [ ] **Доступ к сессии — только владельцу.** Ссылка ?session=UUID
       остаётся для шеринга, но через явный share-токен («поделиться
       отчётом» генерирует ссылку), а не через сам session_id.
4. [ ] **Валидация загрузки до пайплайна:** ffprobe (это вообще видео?
       длительность? кодек?), проверка MIME и magic bytes, кэп
       длительности. Отказ — сразу 422 с человеческим текстом (паттерн
       уже есть для training_platform).
5. [ ] **Rate limiting и квоты:** на IP до логина, на аккаунт после;
       квота free-тира из Этапа 0. Очередь: приоритет у коротких клипов,
       один аккаунт не может занять все воркеры.
6. [ ] **Транспорт и заголовки:** HTTPS везде (платформа даст), CORS
       только на прод-домен (ALLOWED_ORIGINS уже есть), CSP, HSTS,
       X-Content-Type-Options, Referrer-Policy.
7. [ ] **Секреты:** ключи API только в секрет-хранилище платформы;
       проверить историю git на утечки; ротация ключей перед запуском.
8. [ ] **Бэкапы:** ежедневный дамп Postgres + версионирование бакета;
       один раз ПРОВЕРИТЬ восстановление из бэкапа (бэкап без теста
       восстановления — это лотерея).

**Gate 2:** чужой отчёт нельзя открыть подбором URL; мусорный файл
отклоняется до GPU; секретов нет в репо; восстановление из бэкапа
отрепетировано.

## Этап 3 — Качество разбора (параллельно этапам 1–2)

Это продукт про доверие к числам — качество и есть фича.

1. [ ] **Калибровка порогов.** attribution.py честно помечен
       «пороги некалиброванные». Собрать 20–30 клипов разных игроков,
       рангов, разрешений и сенс (попросить знакомых, дискорд), прогнать
       движком, вручную разметить «согласен/не согласен с вердиктом»,
       подкрутить пороги. Это главный источник «ошибок» продукта —
       не код, а неоткалиброванные суждения.
2. [ ] **Матрица входных форматов:** 1920×1080 / 2560×1440 / 16:10 /
       21:9, 30/60/144 fps, вертикальные обрезки из телефона, битые mp4.
       На каждую комбинацию — тест: либо корректный разбор, либо
       понятный отказ. Сейчас всё калибровалось на одном сетапе — это
       известный риск обобщения (см. историю с YOLO-генерализацией).
3. [ ] **Мониторинг groundedness:** coach_failed уже деградирует мягко;
       на проде логировать долю и причины. Цель: < 5% сессий. Рост —
       алерт (обычно значит, что провайдер обновил модель).
4. [ ] **E2E-тесты Playwright:** happy path (upload → прогресс → отчёт),
       пустой клип, битый файл, сеть моргнула при поллинге. Смоук-скрипт
       со скриншотами уже есть — довести до assert'ов и в CI.
5. [ ] **Нагрузочный прогон:** 10 клипов одновременно на staging —
       очередь живёт, времена предсказуемы, память воркера не течёт.

**Gate 3:** корпус форматов проходит; пороги калиброваны на живых людях,
а не на двух клипах; E2E зелёные в CI.

## Этап 4 — Staging, CI/CD, деплой (≈ 3–5 дней)

1. [ ] **Docker-образы** api и worker; фронт — статический билд.
2. [ ] **Хостинг (рекомендация):** фронт — Cloudflare Pages; API+worker —
       Fly.io или Railway; Postgres — Neon/Supabase; Redis — Upstash;
       GPU — Modal/RunPod. Всё управляемое: на этапе беты администрировать
       свои серверы — трата фокуса.
3. [ ] **Два окружения:** staging (то же всё, дешёвые тарифы) и prod.
       Любое изменение проходит staging.
4. [ ] **CI (GitHub Actions):** pytest (353) + npm build + E2E на PR;
       деплой на staging из main автоматически, на prod — вручную по тегу.
5. [ ] **Откат:** деплой по докер-тегам (откат = передеплой предыдущего
       тега), миграции БД только обратимые/аддитивные, файл CHANGELOG.
6. [ ] **Домен, DNS, TLS,** мониторинг аптайма (UptimeRobot/Betterstack)
       со звонком в Telegram/Discord.

**Gate 4:** пуш в main сам доезжает до staging; прод разворачивается и
откатывается одной командой; алерты приходят.

## Этап 5 — Закрытая бета (2–4 недели)

- [ ] 20–50 игроков по инвайтам: свой круг + дискорды аим-тренинга.
      Отдельный Discord-сервер продукта — канал багов, канал «мой отчёт».
- [ ] В отчёт — кнопка фидбека: «вердикт совпал с ощущениями? да/нет +
      комментарий». Это данные для калибровки Этапа 3.
- [ ] Смотреть метрики еженедельно: доля COMPLETED, медиана времени
      разбора, coach_failed, возвраты (второй клип того же аккаунта —
      главный сигнал ценности).
- [ ] Пересчитать юнит-экономику на реальном трафике.

**Gate 5:** ≥ 95% сессий COMPLETED; медиана разбора ≤ 10 минут; есть
игроки, вернувшиеся со вторым клипом; фидбек по вердиктам преимущественно
«совпало».

## Этап 6 — Юридика и публичность (параллельно бете)

- [ ] **ToS + Privacy Policy.** Ключевое: видеозапись — персональные
      данные; описать хранение (7 дней клип, отчёт — пока аккаунт жив),
      удаление по запросу (кнопка «удалить сессию/аккаунт» — сделать),
      передачу кадров VLM-провайдеру (Anthropic/Google) для генерации
      объяснений — это надо явно указать.
- [ ] **Riot.** Продукт не взаимодействует с клиентом игры и не читает
      память — только загруженное видео; это вне анти-чит рисков.
      Сверить текст с Riot «Legal Jibber Jabber» по фан-контенту,
      добавить дисклеймер «not endorsed by Riot Games» и не использовать
      их арты/логотипы.
- [ ] Возрастная планка как у самой игры (16+ по региону) — строка в ToS.
- [ ] Почта поддержки + страница «как удалить свои данные».

**Gate 6:** юрист-ревью или, минимум, самопроверка по чеклистам GDPR
для маленького SaaS; дисклеймеры на месте.

## Этап 7 — Публичный запуск

Чеклист дня запуска:

- [ ] Лендинг: hero нового HUD + **живой демо-отчёт** по ссылке (образцовая
      сессия без логина) — конверсия «понял ценность до загрузки».
- [ ] Лимиты и алерты перепроверены; дежурство первых 72 часов (кто
      смотрит Sentry и очередь).
- [ ] Каналы, по одному в день, не всё сразу (чтобы нагрузка росла
      ступенями):
      1. Discord-сообщества аим-тренинга и KovaaK's,
      2. Reddit r/VALORANT (формат «разобрал свой аим по кадрам —
         вот что нашёл движок», пост-история, не реклама),
      3. TikTok/Shorts: 30-секундные разборы «прицел ждал ниже линии
         головы — вот кадр».
- [ ] Кэп новых регистраций в день (фича-флаг), чтобы всплеск с Reddit
      не положил GPU-бюджет.

## Этап 8 — Пострелиз

- Воронка: визит → загрузка → COMPLETED → второй клип. Чинить самый
  большой обрыв, по одному за раз.
- Платный тир (когда free-квота станет тесной реальным игрокам):
  больше клипов, тренды по профилю, приоритет очереди.
- Продуктовый роадмап из бэклога: двухсигнальная прогрессия KovaaK's
  API (следующее по плану), тренды профиля между клипами, сравнение
  «месяц назад vs сейчас».

## Реестр рисков

| Риск | Вероятность | Митигция |
|---|---|---|
| Пороги вердиктов врут на чужих сетапах | высокая | Этап 3: корпус форматов + калибровка на бете; вердикты «гипотеза» по умолчанию при малых данных (уже так) |
| Счёт за GPU/VLM взлетел | средняя | квоты, кэп длины клипа, кэп регистраций, алерт на дневной расход |
| Провайдер коуча сменил модель/цены | средняя | мульти-провайдерность уже есть; фолбэк + деградация coach_failed |
| Утечка чужого отчёта | низкая | Этап 2: доступ по владельцу + share-токены |
| Загрузка вредоносных/чужих видео | средняя | ffprobe-валидация, ретеншн 7 дней, кнопка удаления, DMCA-процедура в ToS |
| Riot-претензия к имени/артам | низкая | нейтральное имя, свои арты, дисклеймер |
| Один мейнтейнер (bus factor) | высокая | всё управляемые сервисы, IaC-заметки в docs/, runbook «что делать если» |

## Definition of Done «продукт в сети»

1. Незнакомый человек с телефона регистрируется через Discord, загружает
   клип и через ≤ 10 минут читает отчёт — без участия автора.
2. Рестарт любого компонента не теряет ни одной сессии.
3. Ошибка любого этапа пайплайна показывает игроку понятный экран,
   а автору — алерт.
4. Данные игрока можно удалить кнопкой; бэкап восстанавливали руками
   хотя бы раз.
5. Себестоимость разбора известна и покрыта квотами.

**Порядок работ:** 0 → (1 ‖ 2 ‖ 3) → 4 → 5 → (6 ‖ бета) → 7 → 8.
Реалистичный срок до публичного запуска при текущем темпе: 6–9 недель,
из них половина — бета и калибровка, не код.
