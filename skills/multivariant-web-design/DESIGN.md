# Дизайн: расширение навыка multivariant-web-design

Дата: 2026-07-16
Статус: одобрен, готов к реализации

## Задача

Навык `multivariant-web-design` создан в desktop-приложении Claude и опирается на
три источника (reactbits.dev, uiverse.io, styles.refero.design). Нужно:

1. расширить каталог источников найденными в ресёрче;
2. перенести навык в Claude Code (`~/.claude/skills/`), где нет desktop-артефактов;
3. не размыть суть навыка — правило трёх вариантов.

## Решения

| Вопрос | Решение |
|---|---|
| Форма | Расширить существующий навык; каталог вынести в `references/` |
| Площадка | Claude Code, личный навык (`~/.claude/skills/`) |
| Стек | Общий/личный, стек выбирается по проекту |
| Подача вариантов | Три локальных HTML-файла + `index.html`-переключатель |
| Резка каталога | По механизму доступа к коду, не по категориям |

## Структура

```
~/.claude/skills/multivariant-web-design/
  SKILL.md              # процесс: 3 варианта, подача, чек-лист (грузится всегда)
  references/
    sources.md          # каталог источников (грузится по требованию)
  DESIGN.md             # этот документ
```

Два рабочих файла. `SKILL.md` остаётся коротким, чтобы не занимать контекст на
каждом обращении; `sources.md` читается только когда реально нужен источник.

## Что сохраняется без изменений

Суть навыка не трогаем:

- правило трёх направлений: A «продуктовый», B «живой», C «характерный»;
- требование заметного различия между вариантами и пояснения к каждому;
- осознанный выбор тёмной/светлой темы;
- лицензионные правила и атрибуция;
- ключевое правило «не воспроизводи чужой компонент по памяти — загрузи или попроси».

## Что меняется в SKILL.md

| Было (desktop) | Стало (Claude Code) |
|---|---|
| «Отдавай каждый вариант отдельным артефактом» | Папка `design-variants/` с `a-*.html`, `b-*.html`, `c-*.html` и `index.html`-переключателем; открыть в браузере |
| `web_fetch` | `WebFetch` |
| Источники описаны инлайн | Указатель: нужен источник → читай `references/sources.md` |

Чек-лист обновляется под новую подачу и пополняется двумя новыми правилами (ниже).

## references/sources.md — резка по механизму доступа

Ключевое наблюдение: Magic UI, Aceternity, Motion Primitives, Cult UI и
Origin UI/coss — это **не пять источников, а один механизм** (shadcn-реестр).
А Mobbin и Godly не отдают ничего, кроме пикселей. Значит группировать нужно по
тому, как агент добирается до кода — каждая группа тогда становится инструкцией к
действию, а не списком ссылок.

### 1. Готовые спеки — забираются как есть

- `styles.refero.design` — 2000+ машиночитаемых дизайн-систем реальных продуктов.
  Каждый стиль имеет `DESIGN.md`: токены, шкала типографики, спейсинг, Do/Don't,
  CSS custom properties, блок Tailwind v4.
- Приём: назван стиль или дана ссылка → `WebFetch` его `DESIGN.md` → верстать
  строго по его токенам.
- Каталог: `https://styles.refero.design/`, стиль: `/style/<uuid>`.
- Refero MCP — использовать, если подключён.

### 2. shadcn-реестры — агент читает код сам

Общий механизм для всей группы (подтверждён по ui.shadcn.com/docs/registry/namespace):

```bash
npx shadcn@latest view @magicui/marquee      # прочитать код ДО установки
npx shadcn@latest search @magicui --query "text"
npx shadcn@latest add @magicui/marquee       # установить
```

Реестры объявляются в `components.json`. **Namespace выбирается самостоятельно** —
настоящий идентификатор реестра это URL, а не имя после `@`:

```json
{
  "registries": {
    "@magicui": "https://magicui.design/r/{name}.json",
    "@aceternity": "https://ui.aceternity.com/registry/{name}.json"
  }
}
```

Состав группы: shadcn blocks (`ui.shadcn.com/blocks`), Magic UI, Aceternity UI,
Motion Primitives, Cult UI, coss/Origin. Поиск реестров: `registry.directory`,
`ui.shadcn.com/docs/directory`.

URL реестров выше проверены 2026-07-16. Для остальных источников группы URL
берётся из их документации в момент использования — не подставлять по догадке
(см. «Протухание»).

Важно: `view` работает и там, где ставить нельзя — код можно прочитать и
перенести руками (см. стек-гейт).

### 3. Сниппеты — код нужен от пользователя

- **uiverse.io** — кнопки, чекбоксы, тогглы, карточки, лоадеры, инпуты на чистом
  CSS/Tailwind. Лицензия MIT: код можно брать напрямую, сохраняя атрибуцию.
- **reactbits.dev** — анимированные React-компоненты; сильнее всего фоны
  (Aurora, Beams, Particles — WebGL) и анимации текста. Лицензия официального
  репозитория (DavidHDev/react-bits) — MIT + Commons Clause: нельзя продавать
  продукт, ценность которого именно в этом коде.
- Оба сайта — SPA, `WebFetch` отдаёт только мета-теги. Реальный код: GitHub,
  ReactBits MCP (135+ компонентов), или попросить пользователя прислать.

### 4. Галереи — для человека, не для агента

Mobbin, Godly, Land-book, Awwwards, siteinspire. Отсюда код не достаётся —
смотрит пользователь и присылает ссылку/скриншот. Помечено явно, чтобы агент не
ходил туда впустую.

### 5. Системный слой — инструменты (другая ось)

Секция режется **не по механизму**, и это подписано прямо, чтобы не притворяться,
что деление одно:

- **tweakcn** (`tweakcn.com`) — редактор тем shadcn, живое превью, экспорт в Tailwind.
- **Realtime Colors** (`realtimecolors.com`) — проверка палитры и шрифтов на макете.
- **Fontshare** (`fontshare.com`) — бесплатные шрифты для коммерческого использования.
- **Lucide** (`lucide.dev`) — иконки, идут в комплекте с shadcn.

## Два новых правила

### Стек-гейт

Перед установкой из реестра проверить, что в проекте есть Tailwind и
`components.json`. Если нет — **не** запускать `shadcn add`: прочитать код через
`view` и перенести вручную, либо взять источник из другой группы. Пример проекта,
где гейт срабатывает: CRA + чистый CSS с токенами в `src/index.css`.

### Протухание

Источники меняются быстро: Origin UI за год переименовался в coss ui, переехал на
Base UI и сменил домен (`originui.com` → `coss.com/ui`, legacy на `coss.com/origin`).

Отсюда:

- каталог хранит **механизмы и стабильные точки входа**, а не заученные списки
  компонентов и версий;
- если источник не отвечает или переименовался — сказать вслух, а не гадать;
- в спорном случае проверить, а не воспроизводить по памяти.

## Критерии успеха

- Навык срабатывает в Claude Code на запросах вида «сделай лендинг», «набросай UI».
- `SKILL.md` остаётся компактным; каталог грузится только по необходимости.
- Правило трёх вариантов сохранено, подача адаптирована под терминал.
- Каждая группа каталога отвечает на вопрос «откуда здесь берётся реальный код».
- Ни один источник не описан по памяти без возможности проверки.

## Вне области

- Не трогаем `frontend-design` — навык по-прежнему опирается на него в вопросах
  базового качества вёрстки.
- Не собираем `.skill`-архив для desktop (решено: только Claude Code).
- Не переводим valorant-проект на Tailwind.
